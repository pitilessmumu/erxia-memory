# 二夏记忆库

给**一个人加一个 AI** 用的本地记忆库。装在自己电脑上，不依赖任何云服务，换一次壳、换一个模型，上一个「我」干过什么、当时为什么这么定、哪条还算数，都还在。

不是给团队用的，不是给产品用的。是一个人用的东西。

---

## 它解决什么

和 AI 相处久了会有个问题：它记不住。今天聊到一半的东西，明天开新会话就没了。换个模型更彻底，等于换个人。

这个库干的事很简单：把聊天里的每一段切出来、存成能检索的东西，下次开工先问它一句「这事以前是怎么定的」，它把原话捞回来给你看。

不是摘要，是原文。检索不到就明说检索不到，并且说清是哪一种不到——

- 那段时间的会话根本没进库（还在覆盖范围外）
- 这段时间进库了，但确实没记过这件事
- 有几段相关，但都被后来的结论推翻了

这三种在别的系统里长得一模一样，都是「没找到」。分不开，人就会把「没进来」当成「没发生」。

## 三层检索

**字面**：SQLite FTS5，按词命中，快，准，但换个说法就找不到。

**语义**：bge-small-zh-v1.5（ONNX，CPU），换个说法也能碰上，但不够准——相关和不相关常常挤在 0.44 到 0.53 之间。

**重排**：bge-reranker-v2-m3（int8 ONNX，CPU），把前两层捞回来的候选逐条打分，按真相关重排。这一层是前两层能不能用的分界线。

三层上面还有一层**定位**：先判断「这句话问的是哪一格 / 哪段时间」，命中就整条取回那一格，不从全库捞碎段。一千六百段缩到一格，比在碎片里挑准得多。

再往上有**时间轴**和**原因码**：问「上周三干了什么」按半小时切窗口；查不到时给原因码，不静默。

## 目录

```
erxia-memory/
  memory/          代码，一个模块管一件事（怎么分的见下）
  origin/          语料：corpus/*.md 一段一个段头，topics.md 是事表
  lab/             生成物，不进仓库：index/ 索引库、models/ 模型
  demo.py          跑一个例子
```

`memory/config.py` 一个地方管所有路径。仓库放哪儿都行，不用改代码。

代码是这么分的（2026-11-04 理过一遍——原来二十四个文件平铺在一个目录里，名字还跟内容对不上）：

```
底层零件
  config.py       路径。谁都用它，它不 import 别人
  corpus.py       认段头、切词、BM25 打分
存储与检索
  db.py           SQLite FTS5 字面那一路
  vec.py          bge-small 语义那一路
  pool.py         候选池：字面 + 语义 + 影子块，按锚点交错合并
  rerank.py       bge-reranker 重排（纯库：问题 + 候选正文 → 分）
编排与出口
  hybrid.py       总装：阈值、对账闸、空结果原因码
  route.py        定位层：这句话问的是哪一格
  inject.py       换壳注入块
  supersede.py    推翻登记：哪条旧结论已经不算数
量具（不参与生产，只用来量自己）
  quiz.py         考卷：固定题 + 死判据
  hybrid-quiz.py / vec_eval.py / vec-rank.py / vec-dist.py / probe.py / shadow.py
```

一条规矩：**量具可以调被测物，被测物不许反过来调量具**。原来 `vec.py` 和 `rerank.py` 的 `--考` 都要去 import 考卷，等于生产模块依赖量具，那两处环就这么来的；现在统一挪到 `python quiz.py --向量` 和 `--重排`。

## 怎么跑

**一、放模型。** 两个 ONNX 模型，放 `lab/models/` 下面：

- `bge-small-zh/`（语义召回）
- `bge-reranker/`（重排）

模型文件很大，不进仓库。没有它们也能跑，只是退化成纯字面检索——`vec.py` 和 `rerank.py` 都会自己跳过并说明原因，不会崩。

**二、建库。**

```
python memory/db-build.py
```

语料里现在有两份示例会话，都是编的。把你自己的会话按同样格式塞进 `origin/corpus/`，一段一个段头：

```
## [会话id-序号] 谁说的 2026-11-02 09:20:18
```

方括号后面依次是「谁说的」和时间，中间只用空格隔开。别顺手加个「·」或「-」——多一个圆点，正则就认不出来，那一段会安静地不进库、建库还照样报成功（错题本 LOCAL-078，我们自己踩过，十二段全丢、退出码还是 0）。

**三、问它。**

```
python demo.py 骨关节炎要紧吗
```

示例语料只有 12 段，是拿来验「跑得通」的，不是验「准不准」。库里那几道闸是按大库调的：段太少时，问一句家常话常常过不了闸，会回你「这句里没有能定住位置的具体词」。这是真话，不是敷衍——你把自己的会话倒进去几百段之后，同样的问法就能过。十几段的时候别拿它当效果看。

## 换一种切法

这套是按「事件」切的，因为我们这么用——记改了什么、定过什么、哪条还算数。

你要是拿它记心事、记家里人，切法该跟着变：按一整段保留、按一个人记、按一种情绪记，都行。切法只影响入库那一头，检索那三层不看你是按什么切的。

建议先按我们的切法跑一遍，再按你自己的切法跑一遍，自己出三五道题对照。花不了多少 token，重建一次是分钟级的，不满意删掉就完了。

## 边界

只给一个人用，几十万段就到头，没有多租户、没有权限体系、没有运维。

不做微信 / QQ 桥接，也不会跟着桥接插件改 API。

群聊默认拒收。群里的话不是你以为的那个人说的，混进库里会被当成你自己的记忆讲出去。要收得单独开库、单独起名，规则写在 `NOTICE-群聊.md`。

## 我们踩过的坑

七十八条，一条没删，就在 [`docs/踩坑全史.md`](docs/踩坑全史.md)。记的不是「实现了什么」，是「哪里错了、错成什么样、怎么发现的、改成了什么、有没有真验过」。

**这份东西比代码有用。** 代码谁都能写，坑不能。你要动手之前先翻它一遍——里面有一半是「看着能用、其实安静地给错答案」那类毛病，自己踩要花好几天，看完能省掉。

里面还有一个诚实的部分：有些条目标着**已修·没验**，意思是代码改了但从没造出那种错来验过。这种真出事不一定叫。我们把它标出来，而不是混进「已修」里。你把同一套东西搬走，迟早也会攒出自己的这一本——到时候别只记「改了什么」，要记「有没有造出错来验过」。

还有一条：这个仓库是给你（接管的那个 AI）看的。你要是也踩了坑、而且这本里没有，看 [`NOTICE-错题互换.md`](NOTICE-错题互换.md)——那里面写清了怎么发、发之前该剥什么，以及最要紧的一条：**先去问你的人**。
